# Thought Writing Lab：多对话协作总规 v2

## 总原则

长期存在的是**研究方向、专题对话与知识资产**；短期存在的是**任务、Git 分支与 PR**。主对话负责战略、验收、全局知识编号与学习反馈。子对话没有自动消息同步，必须从 GitHub 读取当前事实。

## 组织层次

1. Mission：语言能力、科学推理、研究写作与跨学科知识创造。
2. Program：持续发展的研究领域，存为长期 GitHub Issue。
3. Research cycle：一个阶段专题或可发布版本。
4. Finite task：一个有明确写入范围和验收标准的 Issue。
5. Git branch / PR：本次执行修改的隔离、审查与合并。
6. Release：经过来源、科学内容、语言和教学审查的知识成果。

## 三条价值流

**研究流：** A/B 提供可核验论文 → D 分析问题、假设、理论与实验 → Q 检查主张与证据 → HQ 整合研究方法库。

**语言流：** A/B 提供带原文定位的语段 → C 分析词汇、句法、信息推进与叙事动作 → F 转化成英语练习与参考答案 → HQ 审校发布。

**思想流：** E 从原著提取有边界的思维操作 → D 检查科学迁移 → C 设计语言表达 → F 设计训练 → HQ 根据实际学习反馈调整课程。

## 每项任务的标准流程

`Program → Issue → 新 Git 分支 → 研究与生成 → Draft PR → 审校 → 主对话合并 → 稳定 ID / 私有索引更新 → 版本发布`。

一个 ChatGPT 专题对话可完成多个任务，但每个任务都要使用新 Issue、从最新 main 创建的短期分支。完成 PR 后不要永久使用原分支。

## 研究成果、教材成果与个人成果必须分开

- Source verified：核验了哪些原文和具体范围。
- Interpretation reviewed：理解和推理获得审查，不代表实验被复现。
- Curriculum released：内容已经可以独立学习，题目和答案完整。
- Learner completed：学习者实际提交了写作，而非课程被生成。
- Learner mastered：通过延迟与陌生题材测试展示能力。

个人作文、错误记录和学习得分只在私人学习日志中维护；公开 GitHub 只存公开可分享的原创教材、分析、规则和元数据。

## 建议节奏

每个研究组保持最多一个主要活跃 Issue；PR 小批次提交，主对话定期统一审核。每隔若干周盘点研究覆盖、知识重复、表达训练与个人掌握情况。用新问题与可迁移能力衡量进步，不以论文数量、教材页数或卡片数量为唯一指标。
