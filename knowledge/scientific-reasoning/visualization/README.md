# D 组候选方案｜HTML 科学推理可视化 × PDF 专题讲义

> 2026-10-15 讨论稿，仅属于 D 组 Issue #5 的授权路径；**不修改全局网站技术栈、正式 schema、共同 ID 或 F 组讲义规范**。本稿供 HQ #1、C、A/B、E、F 审议。

## 核心产品界限

- **HTML = 科学研究的可交互空间**：资料索引、科学对象筛选、跨论文比较、证据源跳转、主张/替代解释并排、假设—实验的关系探索和使用条件诊断。它体现知识不断生长；**可视化必须展示关系而非仅给 markdown 加主题配色**。
- **PDF = 经教学编辑的专题学习作品**：明确前置知识、概念讲解、详细案例、分层训练、独立答案与复盘路线。不能把当前网页简单打印为“专题讲义”。编辑者为每章重新选择案例、重组线性叙事并检验可学习性。
- **唯一事实源不是 HTML 或 PDF**：论文定位/核验状态/引用及自有概念记录由结构化数据维护。两类成品都是从来源记录与审核后的分析对象取材，不彼此爬取/人工转录为权威事实。

## 四个彼此独立的研究坐标

- **R 科学思维**：研究对象、隐含假设、理论、竞争解释、可识别性、实验。
- **W 语篇叙事**：引入背景、识别矛盾、问题转折、研究贡献定位。
- **L 语言表达**：主体—动词—客体、搭配、句法、信息结构、可使用语境。
- **E 证据论证**：作者原主张、审稿者意见、独立解释、证据和外推条件。

请勿因为一个句子标记为「反驳/转折」就自动推导其科学问题是反事实识别；两者需要独立标注与审查。以上为概念性映射，公共标签由 HQ 审定。

## 建议的最小记录接口

字段分开三部分：
1. `source`: `source_key`, `official_url`, `source_version`, `locator`, `checked_scope`, `evidence_status`。
2. `analysis`: `analysis_key`, `reasoning_move`, `research_object`, `claim`, `alternatives`, `discriminating_test`, `boundary`, `interpretation_status`。若来源为特定论文，只能声称该论文真的写出的内容。
3. `presentation`: `html_view`, `pdf_topic_candidate`, `reader_goal`, `exercise_ids`。这个展示索引不负责批准课程或改动 F 的专业标准。

原文长引、PDF/EPUB 文件和私人 Drive/Zotero 标识不能写公开 HTML 数据源。详情参见 [local example JSON](D_PROVENANCE_SCHEMA_PROPOSAL.json)。

## 技术选型与注意事项（提案，不要求即刻安装）

**第一阶段：无框架纯 HTML/CSS/JS + 结构化 JSON**。保证 GitHub/本地可审核、可复制、离线可读，避免过早投入大型前端框架。

**扩展阶段**：Quarto 适合网站导航、多格式文档及 OJS 嵌入；复杂可视化可以使用 Observable Plot / SVG / D3。简单示意可使用 Mermaid，但默认严格安全级别禁用点击，因此不宜为了交互随意调成 loose。PDF 已有 XeLaTeX/ctex 工作流无需废弃；若将来追求同源 CSS 印刷，可比较 Vivliostyle，但需保留教学编辑工序。

官方文档：
- Quarto：<https://quarto.org/docs/interactive/>、<https://quarto.org/docs/publishing/github-pages.html>
- Observable Plot：<https://observablehq.github.io/plot/getting-started>
- Mermaid：<https://mermaid.js.org/config/usage>
- Vivliostyle：<https://docs.vivliostyle.org/>
