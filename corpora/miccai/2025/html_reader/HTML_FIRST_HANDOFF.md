# A → HQ / B / C / D / E / F：HTML 主阅读界面与 PDF 专题讲义

日期：2026-10-15。用户决定：HTML 作为日常“可视化”的主要工具；PDF 用于专题讲义总结。

## 一、发布分工

**HTML 是持续扩展的研究与学习界面；PDF 是有教学目标的阶段性成果。** 共用知识底稿，但采用不同的编排逻辑。不是把 Markdown 改扩展名，也不是把整站打印成讲义。

- HTML：按问题、论文、段落、词句、研究动作、跨域关系和练习进入；在同一对象上切换宏观—中观—微观；呈现可定位的来源及编辑分析。
- PDF：选定一个专题，按“学习问题—精读样例—比较—方法提炼—练习—单独答案—复盘”组织。它可以有独立的过渡说明、目录和习题，不必与网站目录相同。
- 知识底稿：保留 Markdown / QMD、来源键、段落定位、内容类型和关系。HTML 与 PDF 是不同视图，而非两份需要手工同步的内容库。

## 二、统一阅读单元（候选接口，不修改中央分类）

每项内容保留：`local_key`、`source_key`、`source_revision`、`source_locator`、`content_kind`、`parent_unit`、`relations`、`owner_track`。研究组的局部分类携带命名空间和版本，不能再将 C 的 discourse 标签当作 D 的科研操作。

`content_kind` 至少区别：作者短引文、上下文释读、编辑分析、原创改写、教学练习、参考答案。默认正文保持连续阅读，微观说明与答案按需展开；来源/版本放入可展开的侧栏，避免审计文字占据正文。

关系应说明用途：本段引出哪个问题，这个表达实现哪个动作，另一篇提供什么对照，练习训练哪项能力。不要只有一张无解释的连接图。

三篇：C²MAOT / Locor / PRECISE-AS。内容快照：`e1f2c4cfee82109176c58b5409b29ea85d356d39`，来自 `corpora/miccai/2025/deep_readings/`。页面展示研究主线、引言推进、方法分工、讨论回扣、原创句法例子、术语说明、练习和折叠答案。

已实现：样例内段落检索与跳转、三篇切换、三篇对照、其他组的已核对入口、专题选材单导出、个人试写导出与本机保存尝试。专题选材 JSON 不包含私人试写。

样例本身无外部脚本、字体或样式依赖；完整笔记/原论文/其他组链接需要联网。保存个人试写不会调用服务器，浏览器拒绝本机存储时提示导出。这个静态样例不具有自动联网更新、跨设备同步或自动论文精读能力。

**测试**：Chromium 注入页面内容渲染，检查桌面与390px窄屏、段落检索跳转、视图切换、选材导出内容和试写导出内容，无JS错误、无整页水平溢出。当前受管理浏览器阻止 file/localhost 导航，故不声称已经验证操作系统双击打开、跨刷新持久化或真实磁盘下载；已验证相应降级提示与导出数据结构。

源码包包含 `reader.template.html`、`reader_data.json`、`build_reader.py`、本交接、接口与测试记录。构建只需要 Python 标准库。当前原型源码包随对话附件交付；本仓库本轮写入的是交接和接口，不把附件链接误称成已部署的网站。

## 五、版本与去重

现有 `deep_reading/` 与 `deep_readings/` 是同一组论文的两份草稿分析，不能按26篇计数，不能当作独立复标。样例按 `miccai:2025:<paper_id>` 去重，固定使用复数目录对应的快照。HQ 应指定最终规范入口，再保留旧路径重定向；本轮不擅自覆盖或删除两份分析。

## 六、发布工具建议与已查官方资料
